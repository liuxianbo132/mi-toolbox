## 0. 执行摘要

### 0.1 核心结论

1. **项目当前是微信小程序原生架构**，没有使用 React/Vue/Taro/uni-app 等前端框架；13 个页面全部由 `pages/*/*.js|wxml|wxss|json` 组成。
2. **现有设计基础已经不是“零规范”**：`app.wxss` 已建立 iOS/Apple 风格设计令牌，包括品牌蓝 `#007AFF`、页面背景 `#F2F2F7`、三级文字灰、三色语义、圆角、间距、字号、阴影和按钮/标签/卡片组件。
3. **品牌 IP 尚未建立**：当前只有一个线性 `cat-home.svg` 图标和一个低透明度 `cat-pattern.svg` 背景纹样，它们是装饰元素，不构成英短银渐层“小咪”的标准视觉资产。
4. **当前 v2 插画与目标风格不一致**：抽样查看 `food.png`、`drink.png`、`yogurt.png`、`shampoo.png`，实际是 3D 轻拟物/黏土质感、带有不透明浅色底板、右下角有“AI生成”水印；不是目标要求的 Modern Flat Vector Illustration，也不是透明 PNG 优先。
5. **现有商品插画可暂用但不建议作为最终品牌资产**：15 张 256×256 PNG 体积小、风格统一、当前映射机制可用，可作为过渡资产保留；最终应新增透明、扁平、无水印的 v3 素材目录，不覆盖、不删除 v2。
6. **品类体系与用户期望的 8 类不完全一致**：数据和契约当前只支持 `food / medicine / daily / other` 四类；`饮料 / 清洁用品 / 母婴用品 / 家居用品` 目前没有正式数据枚举，只能先用关键词物品级插画做视觉补充。若要把它们升级为正式品类，必须另起契约版本，不属于本阶段。
7. **当前截图与当前代码存在版本差**：例如首页代码已是“今日概览 / 今天要处理的物品与用药，一眼看清”，截图仍显示“晚上好，家人！”；物品详情代码按钮已是“移入回收站”，截图仍显示“删除物品”。因此截图只能辅助观察，不能作为当前 UI 的唯一依据。
8. **最合理的推进顺序**：先生成“小咪 IP 标准形象 + 表情动作 + 高频场景插画”，再补齐缺失商品/品类图，最后做设计令牌固化和逐页 UI 集成；不要先改样式再等素材。

]

function categoryIllustration(value) {
  return ILLUSTRATIONS[value] || DEFAULT_ILLUSTRATION

机制评价：

- 优点：映射集中、具体词优先、已避免“水”等单字误命中、未命中时回落分类图。
- 问题 1：关键词是纯字符串包含匹配，可能仍有误判，例如“奶茶”会命中“奶”而不是饮料。
- 问题 2：`牛奶` 与 `食品分类` 共用 `food.png`，语义没有解耦。
- 问题 3：物品详情页 `pages/item/item.js` 使用 `categoryIllustration(row.category)`，未使用 `itemIllustration()`，所以详情与首页/库存列表可能显示不同图片。
- 问题 4：没有“清洁/母婴/家居/饮料”正式分类，只有物品级关键词。
- 问题 5：所有 v2 图都有不透明底板，在列表中被套进圆角容器后看起来像“小方块”，与真正透明插画的轻盈感不同。

- `state-view` 与 `batch-form` 组件结构。

#### 不建议重复生成

- 已有的酸奶、鸡蛋、面包、水果、蔬菜、零食、饮料、药片、纸巾、洗发水物品图：如果 v3 风格全面升级，则属于“全量重制”，不应零散重复生成同题材。
- 已有线性图标：除非整体图标语言从 1.8 描边切换，否则无需再生成。
- 三色语义圆：语义已经稳定，换风格时只换表现，不改红/橙/绿含义。
- `empty.png`：若使用“小咪抱空篮”场景图替代，应在新目录新增，不删除旧图。

#### 真正缺失

- 英短银渐层“小咪”标准形象。
- 小咪头像、表情、动作。
- 15 类功能场景插画。
- 真正的 Modern Flat Vector / 透明 PNG 商品与分类体系。
- 饮料、清洁、母婴、家居的正式视觉表达。
- 统一的空态/成功态/错误态插画语言。

## 4. 完整品牌视觉设计规范

### 4.1 品牌定位

- 品牌名称：小咪工具箱 mi-toolbox
- 品牌 IP：英短银渐层猫咪“小咪”
- 角色性格：Gentle，温柔、安静、友善、有陪伴感
- 品牌情绪：安心、整洁、可靠、克制、家庭感
- UI 风格：现代 Apple 风格，简洁、精致、统一
- 插画风格：Modern Flat Vector Illustration，现代扁平矢量插画
- 使用原则：小咪用于品牌展示、功能引导和空状态，不强行出现在每个卡片或每条列表里

### 4.2 色彩系统

#### 品牌与界面基础色

| Token | 色值 | 用途 |
|---|---|---|
| `--color-primary` | `#007AFF` | 品牌主色、选中态、主交互 |
| `--color-primary-ink` | `#0062CC` | 实心按钮、浅底上的蓝色文字，保证对比度 |
| `--color-primary-light` | `#E9F2FF` | 选中背景、轻提示底 |
| `--color-primary-press` | `#004FA5` | 按压态 |
| `--color-bg` | `#F2F2F7` | 页面背景 |
| `--color-card` | `#FFFFFF` | 卡片背景 |
| `--color-text-1` | `#1C1C1E` | 主文字 |
| `--color-text-2` | `#5F5F64` / `#6E6E73` | 次级文字 |
| `--color-text-3` | `#8E8E93` | 辅助文字、未选中 tab |
| `--color-border` | `#E5E5EA` | 分隔线、描边 |

#### 业务状态色：必须保留，映射固定

| 语义 | UI 文字/标签色 | 插画/强调圆点色 | 浅背景 | 含义 |
|---|---|---|---|---|
| 红 | `#C4271E` | `#FF3B30` | `#FFEAE9` | 过期、危险、禁用、漏服、报废、彻底删除 |
| 橙 | `#A85600` | `#FF9500` | `#FFF2E0` | 临期注意、慎用、待确认、取消计划、库存不足 |
| 绿 | `#1E7B34` | `#34C759` | `#E6F7EB` | 安全、正常、已打卡、进行中、已服 |

规则：

- 红色永远不承担“促销/强调”用途。
- 绿色永远不承担“普通中性”用途。
- 橙色永远不承担“装饰暖色”用途。
- 小咪项圈使用柔和蓝色，不使用红/橙/绿表达情绪，避免与业务状态色混淆。

### 4.3 字体与排版

| 层级 | 当前建议 | 用途 |
|---|---|---|
| 大标题 | 44–52rpx / 600 | 首页标题、详情页名称、大字模式主标题 |
| 区块标题 | 30–34rpx / 600 | 卡片标题、分区标题 |
| 正文 | 28–32rpx / 400–500 | 主要信息、列表名称 |
| 辅助文字 | 24–28rpx / 400 | 日期、单位、说明、标签 |
| 数字统计 | 46–52rpx / 600 | 统计卡、依从率、本月概览 |
| 行高 | 正文 1.45–1.6；大标题 1.2–1.35 | 保持 Apple 克制节奏 |
| 字体族 | 系统默认 | 不引入外部字体，避免包体和加载风险 |

大字模式规则：

- 只放大字号、行高、触控高度与必要内距。
- 不使用 `transform: scale()`。
- 不放大图标、进度条高度、分隔线。
- 每个新增视觉组件都要补 `.large-text` 规则。

### 4.4 间距、圆角、阴影

| Token | 当前值 | 说明 |
|---|---|---|
| `--space-1` | 8rpx | 图标与文字微间距 |
| `--space-2` | 16rpx | 行内间距 |
| `--space-3` | 24rpx | 卡片左右外边距 |
| `--space-4` | 32rpx | 卡片内边距 |
| `--radius-sm` | 10rpx | 标签、小按钮 |
| `--radius-md` | 20rpx | 按钮、输入框 |
| `--radius-lg` | 24rpx | 卡片、弹层 |
| `--shadow-card` | `0 2rpx 12rpx rgba(0,0,0,.04)` | 极轻阴影 |

补充建议：

- 列表行高按内容密度分 88 / 104 / 124rpx 三档。
- 插画容器与文字之间固定 12–16rpx。
- 同页卡片间距保持 16–24rpx，避免局部过密。

### 4.5 组件规范

| 组件 | 规范 |
|---|---|
| 卡片 | 白底、24rpx 圆角、32rpx 内距、极轻阴影；一个卡片只承载一个信息主题 |
| 主按钮 | 蓝底白字、88rpx 高、20rpx 圆角；一屏只保留一个强主按钮 |
| 次级按钮 | 浅灰底深灰字或浅蓝底蓝字；用于“扫码/取消/重扫”等 |
| 危险按钮 | 红色浅底 + 深红字；彻底删除、退出登录、报废等 |
| 标签 | 小圆角、浅底深字；红/橙/绿语义固定 |
| 输入框 | 浅灰底、20rpx 圆角、88rpx 高；标签宽度统一 |
| 列表行 | 左插画、中主信息、右状态/箭头；插画不抢文字 |
| 状态卡 | 大场景插画 + 标题 + 说明 + 单个行动按钮 |
| 进度条 | 绿色/橙色/红色按临期状态变化，轨道用浅灰 |
| tabBar | 81×81 PNG；普通灰、选中蓝；品牌升级可换图形但不换尺寸 |

### 4.6 小咪 IP 规范

#### 固定外观

依据用户给定设定，插画必须稳定保留：

- 英短银渐层
- 圆润饱满的脸型
- 银白色底毛
- 浅灰色渐层纹理
- 黄绿色大眼睛
- 粉灰色鼻子
- 奶白色口鼻和胸口
- 柔和蓝色项圈
- 气质温柔、安静、友善、有陪伴感

#### 比例建议

| 场景 | 建议比例 | 说明 |
|---|---|---|
| 头像 | 头占画面 70% 左右 | 用于个人中心、成员相关 |
| 半身标准形象 | 头身比约 1:1.2 | 用于品牌引导、空态 |
| 全身动作 | 头身比约 1:1.6 | 用于场景插画 |
| 小尺寸图标 | 只保留头、耳朵、眼睛、项圈 | 避免细节丢失 |

#### 使用规则

推荐：

- 首页作为家庭陪伴者，出现在品牌位或空态位。
- 库存空态：小咪抱空购物篮。
- 扫码：小咪拿放大镜。
- 临期提醒：小咪举提醒牌。
- 用药：小咪与药箱互动。
- 家庭共享：小咪与其他成员或猫爪互动。
- 数据备份：小咪抱着文件夹或云朵。
- 低库存：小咪看着空货架。

不推荐：

- 每条商品列表都放猫。
- 把猫叠加在红色危险警告上，削弱风险感。
- 猫的表情过于夸张，破坏 Gentle 性格。
- 使用高饱和霓虹色或复杂渐变。
- 在状态标签中混入猫咪头像，干扰语义色。

### 4.7 插画风格规范

- Modern Flat Vector Illustration。
- 透明 PNG 优先，背景透明度 100%。
- 纯色块 + 少量柔和二级色块，避免复杂写实阴影。
- 允许轻微圆角、柔和叠色，不允许厚重写实投影。
- 统一 3–5px 视觉描边或无明显描边，全项目只能选一种主语言。
- 色板从品牌蓝、中性灰、奶白、浅灰渐层和状态色派生。
- 商品图主体居中，四周保留 8%–12% 安全边距。
- 不出现文字水印、AI 水印、logo、签名。
- 同一系列的光源方向一致，建议左上柔光。

### 6.6 图片验收标准

生成后逐张检查：

1. 背景是否真的透明：用深色/浅色背景各预览一次。
2. 是否有水印或文字：发现即不入库。
3. 小咪五官是否一致：黄绿色眼睛、粉灰鼻子、奶白口鼻胸口、蓝项圈。
4. 风格是否扁平：不接受 3D 黏土、写实摄影、厚渐变。
5. 状态色是否被误用：猫本身不带危险色。
6. 同一场景是否只有一个主体动作：避免信息过载。
7. 缩到 96rpx 后是否仍可辨认主体。
8. 文件命名是否符合上表。

## 8. 各页面 UI 优化方案

### 8.1 首页：从“信息堆叠”改为“陪伴式今日看板”

目标：让小咪成为家庭管理陪伴者，但不干扰危险信息。

建议：

- 顶部家庭标识区保留蓝底白房子，但可把 `cat-home.svg` 升级为小咪头像或小型标准形象，形成品牌锚点。
- “今日概览”区保留三色统计，但统一亮色圆点用于图标、深色文字用于数字标签。
- 临期提醒红条必须保持最高优先级，小咪不叠加在红条上。
- 首页空态可使用 `scenes/home-family.png` 或 `xiaomi/expression-calm.png`，放在“暂无临期物品”区域。
- 快捷入口四个图标保持线性风格，不换成猫表情，避免像玩具。
- 低库存条可使用 `scenes/low-stock.png` 的小尺寸版本，但只作为辅助图。

### 8.2 库存：建立清晰工具区 + 温柔空态

建议：

- 搜索、筛选、清空筛选归为一个“工具卡”，避免多个按钮并列造成噪声。
- 新增物品保持唯一主按钮，扫码作为次级按钮。
- 商品列表插画建议使用 80–96rpx 容器，透明 v3 图可直接放在浅灰圆角容器上。
- 无物品空态使用 `scenes/inventory-empty-basket.png`。
- 搜索无结果使用 `scenes/search-no-result.png`。
- 分类组头使用分类 v3 图，尺寸保持 40rpx；不要使用小咪。
- 位置“未指定”标签保持浅灰，不用橙色，避免与库存不足混淆。

### 8.3 物品录入：把拍照识别做成显眼但不吓人

建议：

- 拍照识别按钮改为独立引导卡：左侧相机图标，中间标题“拍照自动识别”，右侧小咪疑惑表情。
- 隐私提示用小字但提高对比度，不放进警告色。
- 品类 picker 改用 v3 分类图。
- 保存按钮仍保持唯一主按钮。
- 识别成功后可使用轻量 `operation-success.png` 动效/静态反馈，但不阻塞流程。

### 8.4 物品详情：降低密度，统一物品图

建议：

- 物品主图改为 `itemIllustration(item.name, item.category)`，让详情与首页/库存一致。
- 药品物品才显示用药计划和过敏关联；非药品页面保持简洁。
- 批次卡片按状态视觉分区：临期/过期标签明确，但批次卡不要整体染红。
- “移入回收站”使用 danger 次级按钮，和“报废”拉开层级。
- 历史批次默认折叠，保留。
- 空批次状态可展示小咪与空盒子小图，但不要占满屏幕。

### 8.5 扫码：强化前置引导与错误恢复

建议：

- 微信原生扫码界面不可定制，因此优化“进入前”和“失败后”。
- 进入前用 `scenes/scan-magnifier.png` 做简洁说明。
- 失败态保留“已识别条码”，用等宽或更清晰的字号展示。
- 重扫为次级按钮，返回为主按钮。
- 未命中条码进入录入页时，表单顶部显示“已带入条码”，增强连续性。

### 8.6 用药：保持状态优先级，增加陪伴感

建议：

- 今日用药列表保持时间、药名、冲突、状态、确认按钮结构。
- 冲突红/橙标不能被猫咪元素弱化。
- 顶部可放小尺寸 `xiaomi/action-with-medbox.png`，但不要每行放猫。
- 待确认按钮继续用主蓝，已服/漏服继续用绿/红。
- 计划列表中的“取消”用橙色浅底，保持与“慎用”语义一致但不混淆。

### 8.7 用药计划：表单分段化

建议：

- 分为“药品与服药人”“频次与时间”“疗程与漏服判定”三段。
- 过敏冲突提示保持红/橙横幅，位置紧跟药品选择。
- 时间点列表增加序号与删除按钮间距。
- 保存按钮固定在底部或单独卡片，保持可达。
- 使用小咪思考表情仅在“新建计划”标题旁，编辑计划不显示，避免干扰。

### 8.8 依从性报告：图表减负，增加解释

建议：

- 依从率数字仍为第一视觉。
- 低依从率时使用 `xiaomi/expression-concerned.png` 小图，但不能替代红色数字。
- 柱状图增加网格线或基准线，帮助理解 40%/80% 图例。
- 漏服明细保持列表化，不用大面积插画。
- 统计口径说明放在底部，保持小字。

### 8.9 过敏档案：让安全属性更强

建议：

- 顶部使用盾牌图标和小咪安静表情，传达“守护”。
- 过敏原行保持高可读性，删除按钮用 danger。
- 添加输入框下方说明要更醒目但仍保持辅助层级。
- 不使用红色背景铺满页面，避免把表单页变成警告页。

### 8.10 个人中心：重排为“身份/家庭/偏好/数据/管理”

建议顺序：

1. 小咪头像 + 昵称 + 家庭名
2. 家庭信息与邀请码
3. 家庭成员
4. 偏好设置（大字模式）
5. 数据与管理（导出、回收站、操作记录）
6. 退出登录

- 未登录时的大字模式卡与登录后重复，但这是当前设计；品牌化时可保持逻辑不变。
- 小咪头像使用 `xiaomi/avatar.png`。
- 成员行不默认放猫头像，避免与真实成员身份混淆。
- 回收站入口可用 tray 图标，不一定要猫。

### 8.11 存放位置：位置场景化

建议：

- 每个位置行左侧根据名称关键词显示小图标：冰箱、药箱、柜子、抽屉等。
- 当前不接 `locations.kind`，所以先用名称关键词视觉映射，不改数据结构。
- 空态使用 `scenes/location-shelves.png`。
- 删除位置风险说明保持文字，不要用猫表情淡化风险。

### 8.12 操作记录：动作语义图形化

建议：

- 本月概览四类动作增加轻量图标或色点：入库蓝/绿、开封蓝、用完绿、报废红。
- 动作筛选 chips 保持当前实现，但选中态使用 `--color-primary-light`。
- 记录列表可在 action label 前加入小图标，保持 24–28rpx。
- 空态使用 `scenes/records-empty.png`。

### 8.13 回收站：明确“可恢复”和“不可逆”两层

建议：

- 顶部提示卡保持，但“彻底删除后不可恢复”用红色文字或红色小图标强调。
- 空态使用 `scenes/trash-restore.png`。
- 恢复按钮为次级蓝/灰，彻底删除为 danger。
- 物品/批次行可保留品类插画，但尺寸小于列表主图，避免喧宾夺主。

## 10. 结论

当前项目已经有稳定的业务功能、清晰的数据契约和初步的 Apple 风格设计令牌，但还没有真正形成“小咪工具箱”的品牌视觉体系。最重要的缺口不是再补几个按钮样式，而是：

1. 建立唯一、稳定、可复用的小咪 IP；
