# 开工简报 · 测试窗口

## 你是谁

负责小咪工具箱测试的窗口。分两阶段：**先出测试计划（现在就做）**，**后执行验收（前端/后端交付后）**。

## 开工前必读

1. `docs/data-contract.md` —— 「常量」一节是用例判定依据（阈值、漏服 30 分钟、品类集合）
2. `.workbuddy/memory/2026-11-19.md` —— 验收标准与全部拍板结论

## 阶段一（现在）：产出 `docs/test-plan.md`

M1 用例：
- 家庭创建 / 邀请码加入，两个成员互见同一份库存
- 物品 + 批次录入（含「生产日期+保质期天数」换算到期日的正确性）
- 临期分级边界值：药品第 6/7/8 天、普通物品第 2/3/4 天的 level 归属
- 报废 / 用完的批次不再出现在看板
- 新录物品 visibility 默认 'household'

M2 用例：
- 过敏档案维护：本人可改自己的；管理员可代管家人的
- 录药关联「对某成员禁用/慎用」→ 该成员查看时冲突标红
- 用药计划（多时间点 / 每天 / 隔天 / 疗程起止）→ doses 按 plan 自动生成的正确性
- 到点提醒 → 确认打卡 → 时间线状态翻转
- 到点后 30 分钟未确认 → missed → 升级通知家人；阈值改成 60 分钟后判定随动

每条用例四要素：前置条件 / 步骤 / 期望结果 / 问题归属（前端|后端）。

## 阶段二（M1 交付后）

- 按计划逐条执行（真机或微信开发者工具预览），结果回写 `test-plan.md`（通过/失败/证据路径）
- 只记录与归类问题，**不改任何业务代码**；前端后端互相扯皮的结论回总控裁决

## 红线

- 不改 `pages/` `utils/` `sql/`；不删任何数据（测试用数据建在小程序测试账号下）；git push 先问用户
