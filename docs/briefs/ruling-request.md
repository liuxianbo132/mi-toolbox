## R1 到期日换算口径（test-plan §6-#1）

**现状**：`utils/date.js` 的 `calcExpiry` = 生产日期 **+ N 天**（生产当天不计入）。
契约原文：「到期日换算：国内包装只印生产日期+保质期天数 → toDateOnly（utils/date.js 已有）」——契约只指了函数，未定义当天是否计入。

**分歧举例**：生产 2026-11-10、保质期 30 天：
- 现状口径：到期 2026-12-10
- 国内包装惯例（生产当天算第 1 天，+N−1）：到期 2026-12-09

**选项**：

| 选项 | 动作 | 代价与风险 |
|---|---|---|
| A. 维持现状（+N 天） | 零代码改动，契约补一句口径说明 | 与包装真实语义可能差一天，临期提醒**晚一天**触发；对药品场景偏危险 |
| B. 改为 +N−1 | 前端 `calcExpiry` 一行改动（天数减 1），契约写明「生产当天计第 1 天」 | 符合行业习惯；已录测试数据需重录 |

**影响面**：M1-02/M1-03 期望值随裁决修正；录入页换算提示文案；后端无影响（存的是换算结果）。

**测试窗口倾向**：**B**。理由：药品是本项目的核心品类，晚一天提醒是实打实的过期风险；改动成本一行。

## R2 一人多家庭与「退出家庭」能力（test-plan §6-#8）

**现状**：契约未定义。`members` 表结构上允许一人出现在多个 household（多条记录），但 V1 UI 是单家庭流（home 页「创建/加入家庭」二选一）。契约定义的 RPC `join_household` 也没有「已有家庭时再加入」的行为约定，且**没有任何「退出家庭」能力**。

**问题场景**：B 已在家庭 1，误点或再次加入家庭 2 → 库存看哪个？RLS 可见范围怎么算？误加之后有没有出路？

**选项**：

| 选项 | 动作 | 代价与风险 |
|---|---|---|
| A. V1 锁定一人一家庭 | 后端 RPC 加保护（已有 household 时 join 返回明确错误码）；前端按角色隐藏「创建/加入」入口；**需连带拍板「退出家庭」是否纳入 V1**（若无退出，误加只能后端手改数据兜底） | 改动小；但须补退出能力或明确 V1 不做 |
| B. 支持多家庭 + 切换器 | 前端加家庭切换 UI，RLS/查询按当前选中 household 过滤 | 工作量明显增加，超出 V1 最小闭环，不建议本期做 |

**影响面**：M1-01 用例步骤（第三账号 C 的前置设计）；`join_household` 错误码语义（是否新增 `already_joined` 类返回值——若新增，契约需递增版本）；前端 home 流程。

**测试窗口倾向**：**A**，且建议把「退出家庭」最小能力（本人可退出、管理员可移除成员——后者可再议）一并纳入 M1 范围，否则误加场景无解。

## 裁决回执（总控已填写，2026-11-19）

- **R1 结论**：**B 改 +N−1（生产当天计第 1 天）**　契约动作：已写入 `docs/data-contract.md` **v1.2** 常量节；**口径同时扩展到 `calcOpenedExpiry`**（原申请未覆盖该函数，同口径一次改齐，避免同一偏差换个函数再犯）
- **R2 结论**：**A 锁一人一家庭**　是否纳入退出家庭：**纳入 M1——member 自退（leave_household）+ owner 移除成员（remove_member）都做；owner 退出/解散 V1 不做**　契约动作：data-contract.md → **v1.2**（join_household 行为变更 + 新增 create_household / leave_household / remove_member 三个 RPC 约定 + 「成员关系变更语义」节）
- 裁决人：小二（总控窗口）　日期：2026-11-19

### 裁决依据（简）

- **R1**：风险不对称——提前一天提醒只是多看一眼红标，晚一天对药品是真实过期风险；代码成本两行（含 calcOpenedExpiry）。
- **R2**：误加死胡同必须堵；但 owner 解散家庭牵扯级联删除（households ON DELETE CASCADE 已实装），是独立产品题，V1 不混入。成员管理 UI 收敛在「我的」页，home 不动加入后的布局。
- **事实核查**：calcExpiry +N 天行为已在 date.js 第 15 行确认；members 的 `UNIQUE(household_id, owner_id)` 只防同家重复，跨家加入当前无约束——R2 的 RPC 拦截判断必要且真实。

### 各窗口动作清单（按裁决执行）

**前端窗口**
1. `utils/date.js`：`calcExpiry` 与 `calcOpenedExpiry` 各改一行（+N → +N−1）
2. 录入页：换算提示文案注明「生产当天计第 1 天」；到期日保留直接填写路径；`batches.production_date` 落库（v1.1 已补录该字段）
3. home：已加入家庭后隐藏「创建/加入」入口；join/create 收到 `already_joined` → 提示「已在家庭中，请先退出再加入」
4. 创建家庭改调 `create_household(p_name)` RPC（替代旧的两段直接插入，invite_code 由服务端生成）
5. 「我的」页新增家庭成员管理：成员列表 + member「退出家庭」按钮 + owner「移除成员」按钮；owner 不显示退出入口
6. 边界提醒：`locations` / `records` 两表 V1 前端不接 UI（location_id 留空、不写流水）；想扩范围先回总控裁决

**后端窗口**
1. `join_household` 行为变更：已有任一家庭 → `'already_joined'`（覆盖 v1.1 的 ON CONFLICT DO NOTHING 旧语义）
2. 新增 RPC `create_household(p_name text)`（原子建 households + owner 成员；invite_code 服务端生成）
3. 新增 RPC `leave_household()`（owner 调用返回 `'owner_cannot_leave'`）
4. 新增 RPC `remove_member(p_member_id bigint)`（owner-only、限本家庭、限 role='member'；'forbidden' | 'not_found'）
5. `sql/` 留档同步；RLS 不变（成员删除经 SECURITY DEFINER RPC 完成）
6. 原任务 2（定时任务能力验证）继续，结论未出不影响本回执落地

**测试窗口**
1. §6-#1 期望值按 +N−1 修正（生产 2026-11-10 + 30 天 → **2026-12-09**）；补 `calcOpenedExpiry` 同口径用例（开封当天计第 1 天）
2. M1-01 按 already_joined / 退出 / 移除语义修正；新增用例：member 退出后 RLS 不可见原家庭数据；owner 移除成员生效；owner 调 leave_household 被拒
3. join/create 的入参覆盖两类场景：同家重复、跨家重复（返回均应 `already_joined`）

### 总控备注

- M1 范围因 R2 扩大约一个成员管理页 + 三个 RPC——关闭「误加死胡同」的必要成本，接受
- 后端校对已把契约推到 v1.1（真实结构：bigint 主键、joined_at、locations/records 补录），**前端若仍按旧契约开发，请以 v1.2 重新对字段**
- 本回执与契约 v1.2 为同一裁决的两个落点，冲突时以契约为准
