# V3 产品调研与功能取舍（2026-11-24）

## 本轮结论

本轮实现「首页待补货 → 库存仅看待补货」的闭环；不新增家庭购物清单、家庭成员提醒或 OCR 批量入库。实现仅使用既有物品与批次数据，不改云端表、RLS、家庭隔离或保质期 / 用药 / 过敏语义。

## 候选优先级

| 候选 | 用户价值 | 实现 / 数据风险 | 决定 |
| --- | --- | --- | --- |
| 仅看待补货筛选，并由首页待补货卡直达 | 高 | 低 / 极低 | 本轮实现。复用现有 `item.lowStock`，不产生新写入。 |
| 复制待补货名称 | 中 | 低 / 极低 | 暂不做。默认阈值为 0 时无法可靠推导建议购买量。 |
| 可勾选、家庭共享的购物清单 | 高 | 中高 / 高 | 暂缓。需要新表、RLS、迁移、多人冲突与验收。 |
| 临期 / 用药日历 | 中 | 中 / 中 | 后续评估。 |
| 家庭成员漏服通知 | 高 | 高 / 高 | 暂缓。需要授权、通知链路与医疗风险设计。 |
| 小票 OCR 批量入库 | 中高 | 高 / 中 | 暂缓。需要多项识别确认及批量写入保障。 |

## 实现边界

- 低库存阈值为每个物品 `0–999` 的非负整数；留空按 `0`，即用完才提醒。
- 首页跳转意图只保存在内存，并绑定当前家庭；切换账户、无家庭或退出登录时清除。
- 不将「待补货」伪装成购物清单，也不推导未经用户确认的购买数量。
