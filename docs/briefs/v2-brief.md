## Step 1：三页结构重排（本步单独交付验收）

| 页 | 结构要求 |
|---|---|
| 看板 | 顶部漏服红条（保留）→ 统计条（过期/危险/警告三格）→ 三分区卡片列表：已过期区、危险期（按现有阈值 danger）、警告期（warn）；卡片：物品名 + 品类标签 + 剩余天数大字 + 数量 |
| 库存 | 顶部操作区（新增 + 扫码按钮，扫码 Step3 接）→ **按品类分组**（food/medicine/daily/other，组头带计数，空品类不显示组）→ 行卡片：名称 + 品牌规格 + 位置角标（Step2 接，先占位可隐藏） |
| 详情 | 头部信息卡（名称/品类/品牌规格/编辑入口）→ 用药计划区（仅 medicine，保留现有）→ 过敏关联区（仅 medicine，保留现有）→ 在库批次卡片组（到期日大字 + 色标 + 数量 + 开封态 + 操作按钮组：开封/用完/报废）→ 历史批次折叠区 → 危险操作区（删除物品） |

**Step 1 红线**：只改结构与样式，**不改任何业务逻辑/事件行为/文案含义**；事件名全小写；完成后自测 M1 关键路径（录入→看板→库存→详情→报废）与 M2 关键路径（用药计划→打卡）全通，再回报总控。

## Step 2：存放位置

1. 位置管理页：库存页入口 → 列表 + 新增 + 改名 + 删除（删除前先将该家庭 batches.location_id 置空，再删位置）
2. 录入页与新增批次表单加「存放位置」选择器（可不选）
3. 详情批次行显示位置名（未选显示「未指定」）；库存行位置角标规则见契约 v1.8

## Step 3：扫码录入

1. `pages/scan/scan` 实装：进入即 `wx.scanCode({ scanType: ['barCode'] })`；取消/失败返回上一页无副作用
2. 扫到条码 → 查同 household `items.barcode` 匹配：命中跳该物品详情（用户可快速加批次）；未命中跳录入页并预填 barcode
3. 库存页顶部「扫码」按钮入口

## Step 4：操作流水

1. 4 个写入点：批次入库（create）、开封（open）、用完（use_up）、报废（discard）——主操作成功后写 `records`（batch_id、action、quantity、物品名快照 note、owner_id、owner_name 快照）；**写失败静默不阻塞**
2. 查看页：我的页「操作记录」入口 → 时间倒序列表（操作人 + 动作中文 + 物品名 + 数量 + 时间），limit 100

## 白名单纪律（新增字段必须同步，已踩两次坑）

- `ITEM_FIELDS` 需加 `barcode`（Step3）
- `BATCH_FIELDS` 需加 `location_id`（Step2）
- 新建 records access 时 `RECORD_FIELDS` 必须含 `id` + 写入所需全部字段
- **改 `utils/` 后必须「清缓存 → 全部清除 → 重新编译」**（热重载不刷新工具层）

## 验收标准

- Step1：三页结构与原功能等价（冒烟全通）+ 前后截图存 `docs/evidence/ui-v2/`
- Step2：建 2 位置 → 录入挂载 → 库存/详情可见 → 删位置后显示「未指定」
- Step3：真机扫已有条码进详情；扫新条码预填新建；取消无副作用
- Step4：四类动作各一次 → records 4 行正确；模拟写失败不影响主操作
- 每步完成回报总控（附改动清单），Step1 单独验收后再继续
