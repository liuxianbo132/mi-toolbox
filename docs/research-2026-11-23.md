## 四、WorkBuddy 生图能力分析与本项目应用

### 4.1 能力盘点

- **ImageGen**（内置）：文生图 / 图生图（以参考图控制风格），输出 PNG 本地文件；适合**装饰性插画、氛围图、分享卡片素材**
- **VideoGen**：文生/图生视频——本项目无适用场景
- **3D 生成**（multimodal skill）：text-to-3D，仅用于素材展示，小程序运行时无法直接用
- 路由建议：批量任务用**固定 prompt 模板 + 统一风格后缀**，逐张生成后人工筛选

### 4.2 可立即落地（建议先做这两项）

**① 品类插画升级（SVG → ImageGen PNG）**

现插画为手写 SVG（牛奶盒/药瓶/按压瓶/收纳盒），风格统一但"扁平"。用生图可升级为 3D 轻拟物：

> 参考 prompt（食品）：`3D minimalist illustration of a milk carton, soft clay material, pastel palette, gentle studio light, single centered object, plain warm white background, iOS app illustration style, high detail, no text, no logo`
> 风格统一后缀：`... soft clay material, pastel palette, gentle studio lighting, plain background, iOS app illustration style, no text`

生成 4 张（food / medicine / daily / other）+ 2 张空态（空冰箱、空药箱）。

**② 空状态插画**：看板/库存/用药空态使用"柔软 3D 空场景"，提升温度感。

**关键工程约束与解法**：
- 微信**主包 ≤ 2MB**：PNG 单张 50-80KB，6 张约 400KB（占包体 20%），可接受但不理想
- 更优方案：**上传到 WorkBuddy 云存储**，`image src` 使用 https URL → 不占包体、可迭代；保留 SVG 本地兜底（断网时回退）
- 图片加载失败需 `binderror` 回退到 SVG（已有 `mode="aspectFit"`，补 error 处理即可）

**落地步骤**：固定 prompt → 生成 6 张 → 人工选图 → 上传云存储 → 替换 `constants.js` 的插画路径（URL）→ 保留 SVG 兜底 → 真机截图对比。

### 4.3 需进一步评估

| 事项 | 风险/约束 |
|---|---|
| **透明背景抠图** | ImageGen 输出为不透明底；沙箱无抠图工具链。可接受"白底圆角卡片"（与现有卡片风格一致），或引入抠图服务评估 |
| **包体积 / 离线可用性** | 走云存储 URL 则离线不可用；本地打包则占主包。建议：首屏关键 2 张本地、其余 URL |
| **风格一致性** | 多张图需固定 prompt 与筛选标准；建议一次生成 3-4 个变体择优，成本可控（单次 credits 低） |
| **分享卡片**（V3 周报分享图） | 需 canvas 合成文字 + 生图背景，技术上可行，但排期应放在统计功能之后 |

### 4.4 明确不建议

- **tabBar / UI 图标**：生图无法保证 81×81 精确笔画与选中态一致性，现有自建 SVG + PNG 已足够
- **真实商品图片**：AI 生成不能替代用户实拍（真实性与合规）
- **人物/生活场景插画**：涉及隐私与风格风险，收益低

## 六、结论摘要

1. **项目工程质量高于同规模个人项目**：契约/测试/证据/交接四件套齐全，静态检查 108 项全绿，依赖极简，仓库干净
2. **最值得立即做的三件小事**：README（0.5h）、低库存提醒接线（字段已备）、保质期进度条（纯展示）
3. **中期的价值高地**：用药依从性报告（数据已有，只缺聚合视图）、小票 OCR 批量入库、数据导出
4. **生图能力的最佳落点**：品类插画与空态插画的质感升级（走云存储 URL，不占主包），而非图标或商品图
5. **不建议现在动的**：药物相互作用（需知识库）、真实物品图片（动 schema）、深色模式（优先级低）
